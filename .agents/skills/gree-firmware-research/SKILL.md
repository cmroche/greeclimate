# Research properties and quirks

Use after [firmware discovery](../gree-firmware-discovery/SKILL.md), [download](../gree-firmware-download/SKILL.md) and [executable qualification](../gree-firmware-decompile/SKILL.md), before [emulator integration](../gree-emulator-device/SKILL.md). The deliverable is a complete per-source property assessment and source-backed implementation recommendations, not a larger empty identity catalog.

Read current `greeclimate/device_profile.py`, `greeclimate/mid_profile.py`, relevant raw/typed consumers, `gree_emulator` families, fixtures and `docs/HIDS.md`/`docs/MIDS.md`. Private evidence is in sibling `../gree-research/firmware-capabilities/research/`, including `SessionScan-verification.json`, `DecoderNext-verification.json` and their linked source exports. Historical integration, decoder or CLI results do not prove an unexamined property or a new source. In the session assessment, read `SessionQuirks/inventory.json` and the assignment contract; derive scope from inventory rather than hardcoding counts. Preserve originals, old manifests/projects and existing uncommitted integration.

For catalog-wide work, use private `CatalogQuirks/Inventory/inventory.json` and the current owning group assessments, not an old profile/MID count. Reconcile each source/bank and every proposed client/emulator change separately; partial source research is not completed runtime integration.

## Assessment procedure

1. **Enumerate every source file.** Make one row per file/build/region/API variant, even when OTA codes repeat. Record exact hashes and embedded identities separately from OTA aliases and reported identities. Reuse prior probes only after verifying their exact bytes, canonical mapping, primitive boundaries and relevant execution path. Read original bytes/disassembly/callbacks beyond the manifest summary.
   Include every original and independent bank/code-plus-RAM view from the current catalog inventory; an existing profile or prior export does not remove it from scope. Keep source-qualified corrections and superseded forced-store/`BL`-skip results distinguishable.
   Pin decisive instruction and literal bytes in each decompiler export to the original image's exact file offset, destination and segment hash; a JSON source-hash label alone is not provenance. Inspect raw mapped bytes for unrooted branches before inferring absence from incomplete C or instruction listings.
2. **Classify identity and roles.** For each MID, distinguish emitted discovery/enumeration value, configured/mainboard input, route comparison, normalized alias and fallback. Preserve string width, leading zeros and identity widths. Trace normalization and both sides of aliases. No MID from filename, no standalone child inferred from gateway routing, no AC typing inferred from `Pow`/`Mod`/`SetTem` in IR/cache controllers.
3. **Close the dispatched namespace.** Enumerate raw getter/setter tables, callback registrations, binary/serial maps, generated names, aliases and generic handlers. Trace dynamic selection, forwarded JSON/binary payloads and initialization. Strings and public-client polling presets are leads, not the property boundary. Record the address/table range/branch closure establishing completeness, or identify the unresolved route. Opaque forwarding prevents a negative feature claim about the downstream device.
   Before declaring a getter absent, trace RAM pointers, literal copies and constructor/startup initialization. A missing replay initializer can hide an implemented field (including HID); qualify the harness setup rather than turning an omitted initialization into a firmware no-support claim.
   Follow the callback through its actual JSON constructor: a raw nonzero mask passed to a boolean constructor produces JSON true, not that mask as an integer. Conversely a numeric constructor preserves its source width/sign rules. Callback return registers alone do not establish wire type.
4. **Trace end to end.** Follow socket receive → outer parser/target → decrypt/key/padding → inner dispatch → getter/setter or binary route → requested/effective mutation → cache → acknowledgement → independently fresh status. Record cache ownership and lifecycle, mainboard refresh, forwarding and readback. An echoed requested `p` is not proof of stored/effective `val`; an ack alone is not proof of support or physical action.
5. **Assess every actual property.** Record readable/writable/unknown separately, wire type, missing/unavailable value, scalar/array behavior, metadata, order and duplicates, type coercion/rejection, signedness/width, accepted ranges, masks/clipping, units/fractions, unknown/read-only handling, partial/batch behavior and next-status. Include raw fields even without a typed public API. Separate source initialization from mainboard-provided defaults and chosen synthetic model defaults.
   Preserve numeric token spelling when native code applies lexical classification or `atoi`; converting `1e3` to a float first changes behavior. Check exact-capacity and first-hole array paths before assuming limits or whitelist filtering preserve the count.
   Enumerate metadata alongside raw caches. A recognized name may append `cols` without appending `dat`, or append several values; preserve ragged cardinality and distinguish it from an unsupported name. Trace metadata getters independently of similarly named setters, which can write different storage.
6. **Assess transport and topology.** Resolve discovery metadata, UID/HID/MID provenance and types; outer/inner field casing/order where meaningful, key/session selection including integer width/masks, bind/rebind/mate/remate, ciphertext/padding and exact LF framing. Trace roots/children, identity widths, target routes, enumeration/pagination/order, maximums, shared versus isolated cache/key ownership and restart behavior. A reply-buffer size does not prove a receive limit.
   Establish the actual transport before projecting a LAN contract: shared cloud/MQTT callbacks, TCP service, MDF mesh and serial-only paths are not UDP appliance ingress. Qualify plaintext-object `pack` at `i=2` only where dispatched, inner LF before padding separately from outer UDP/TCP LF, and fixed reply-port routing separately from sender-port echo. Do not add a UDP façade to make a non-UDP source consumable.
7. **Evaluate every client profile field.** Use the decision table below for each source, including an evidence-backed unknown/no-change outcome. Differentiate unavailable values, unsupported operations, wire encoding and physical calibration. A missing local string is never a no-support proof; a finite complete dispatched LAN namespace can prove a particular LAN operation absent. Qualify the searched namespace and downstream forwarding limits.
8. **Evaluate every emulator gap.** Compare all reachable operations/properties against the actual family handler, codec, metadata, cache, topology and fixtures. List each missing/mismatched behavior, whether source-qualified, chosen safe policy, or blocked. Do not stop at adding identity/MID tuples, a narrow happy-path fixture or familiar AC fields. A bounded wire model must cover its complete declared dispatched namespace, including raw fields, while explicitly excluding unresolved physical behavior.
   Known getter serialization/mutation must be included even when physical calibration or actual mainboard initialization is unknown. Propose an explicitly chosen synthetic cache/readout with labeled default and lifecycle; retain unknown physical initialization/calibration separately. Only unestablished callback/output/schema/transport semantics block that wire operation, not the lack of measured appliance physics.
9. **Author independent semantic probes.** Reuse native harnesses where sound. Execute original instructions where possible; otherwise author explicitly byte-asserted instruction-matched translations with exact source hashes. Declare every JSON/libc/ROM/crypto/I/O primitive hook and its ABI; never hook the getter/setter, dispatcher, mutation or result being proved. Assert literal expectations independent of client/emulator objects. Cover boundaries, sign/width, invalid types, arrays, duplicates, requested/effective differences, ack and fresh status. Hash/syntax-only checks do not establish semantics.
   Preserve the original binary primitive ABI, not merely a C signature: callers may consume residual return-register values from nominally void JSON helpers. Match the actual cJSON ownership/reference/list semantics. Choose ISA/CPU mode/model at engine creation before register/memory access, and distinguish adapter/setup/decode failures from native faults.
   Keep instrumentation nonperturbing: scope necessary hooks and prefer final-memory inspection over data hooks where possible; verify original conditional branches/flags before calling a divergence a firmware fault. Memory hooks can corrupt ARM Thumb ITSTATE in affected Unicorn versions ([issue #2309](https://github.com/unicorn-engine/unicorn/issues/2309)); fix the harness, never firmware instructions or expected output.
10. **Qualify faults and finish reachable work.** Preserve native faults and exact PC/instruction/trace. Missing ROM/save ABI/peripheral/initialization may bound a probe without blocking a self-contained property routine. A safe chosen atomic emulator model must be explicit and separately tested; it does not convert native partial mutation/fault into native success. Never invent firmware output, full boot, hardware behavior or a blanket hardware blocker.

## Client decisions: every field, every source

`DeviceProfile` stores firmware-code-wide quirks, not exact-HID/version admission shims. Assess all known builds of the code before recommending a shared trait; conflicting/insufficient build evidence remains qualified, not hidden behind a version special case. A legitimate known identity entry may remain trait-empty, but it is not a completed property assessment by itself.

| Field | Required assessment |
| --- | --- |
| `temperature_offset` | Raw LAN sensor encoding and conversion at getter/mainboard/cache boundaries; distinguish a protocol bias from physical sensor calibration. Do not manufacture calibration from plausible room temperature. |
| `relearn_temperature_offset` | Evidence for changing/learned encoding across initialization, status updates or mainboard input, and the client's invalidation/relearning behavior; not a guess from one sample. |
| `buzzer_properties` | Actual readable/writable names, aliases and batch semantics. Client support is opt-in: the default `()` disables automatic buzzer commands and reports unsupported; only qualified usable names enable it. Record unknown versus proven absence separately in research; the client default is not firmware-absence evidence. |
| `cooling_mode_value` | Raw mode selector values, getter/setter conversion and typed-family applicability. Shared field names alone do not establish AC semantics. |
| `capabilities` | Every applicable typed-family capability versus complete namespace/getter/setter evidence, including disabled overrides and unavailable sensor values. Capability column presence is not proof of all values or physical effects. |
| `gateway_dialect` | Root/child protocol, key/target routing, enumeration and lifecycle evidence for the actual code-wide dialect; no inference from a gateway-looking MID alone. |

For `MidProfile`, assess the exact `mid`, ordered `status_columns` and typed `family`, plus consumers deriving capabilities or choosing a device class. Qualify the automatic first poll as well as polling after HID is cached. Preserve raw-only and metadata-only roles. Distinguish supported fields from a polling preset, unsupported from uninitialized, and emitted aliases from stored source MID. Do not assign a typed family merely to expose generic raw fields.

A source-configured or mainboard-reported runtime MID is not a fixed compiled identity. Trace the value through initialization and serialization, retain its provenance in presets, and do not promote route comparisons or neighboring builds to emitted identities.

## Required evidence and output

Use existing private assessment conventions. For the session contract, write only the assigned `SessionQuirks/<group>/` artifacts and produce `assessment.json` with:

- `schema_version: 1`, `group`, `firmwares`, `checks`, `proposed_changes`, `blockers`;
- `checks`: `{command, purpose, proves, boundaries}`, plus actual execution/result references only if run by the authorized owner;
- `proposed_changes`: `device_profiles`, `mid_profiles`, `emulator`, `catalog_rows`, with exact proposed values, affected consumers/fixtures/docs and source evidence; distinguish recommendations from applied changes.

Every firmware row includes `ota_code`, `source_path`, `source_sha256`, `embedded_hids`, `mid_roles`, `assessment_status` (`lan_qualified`, `partial`, or `blocked`), `property_coverage`, `properties`, `quirks`, `transport`, `emulator_gap`, `unknowns`, `blockers`, `evidence`.

- `property_coverage` names the namespace roots/tables and closure proof, unresolved routes and any forwarding boundary; absence of expected strings is insufficient.
- Each actual property has `name`, `readable`/`writable` (`true`, `false`, or `null` for unresolved), `wire_type`, transform/range, `ack_vs_stored`, and evidence path/address/original bytes. Include applicable edge cases from the procedure, not only names.
- `quirks` covers every client field above and wire units/fractions, masks/clipping, types/duplicates/order, unknown/read-only and batch semantics. Explicit no-change/unknown with scope is valid; invented quirks are not.
- A blocker names exact missing bytes/instruction/ROM address/ABI/initialization or companion schema, searched evidence and blocked operation. Physical calibration uncertainty is not a blocker for independently recoverable wire semantics.

Keep source evidence, native results, translated results and synthetic policy separate. Author `probe.py`/helpers and literal fixture vectors where executable qualification is needed; preserve fault evidence even when a safe model is proposed. No public vendor binaries, private captures, credentials, runtime research dependency, generic firmware database/framework or generated `CHANGELOG.md` edits.

## Integration and honest completion

Research-only ownership does not authorize editing shared runtime/catalogs. Hand recommendations and exact independent expected values to the integration owner. A separately authorized integration must update all affected raw/typed callers, factory/gateway paths, exports only where required, profile tables, fixtures, regressions, examples and public/private HIDS/MIDS/support documentation; preserve existing architectural conventions rather than adding compatibility shims.

The integration owner must verify fixtures against the source probes, exercise an actual CLI process with an independent raw peer, command → fresh status and malformed recovery, keys/framing/UID/topology, then exercise the unmodified public client separately. Consumer mismatch is a finding, not permission to falsify emulator behavior. Run focused/full tests and repository gates only when authorized and once edits settle; report exact commands, interpreter, observed results and limits.

In an edit-only assignment, execute no probes/tests/build/lint/formatters: return runnable commands explicitly marked not run. Completion requires a row and complete source-reachable assessment for every assigned file, concrete unresolved prerequisites, and every emulator/client/catalog recommendation accounted for. “LAN qualified” applies only to the declared proved boundary, not a full-firmware ID, full boot or physical device. Finish reachable work before reporting blockers; never claim unsupported from opaque forwarding or unverified success from an authored probe.
