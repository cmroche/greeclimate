# Known HIDs

Gree's `hid` is a composite firmware identifier. It identifies a firmware target and build, not a unique appliance serial number. The app extracts the numeric firmware code from it when checking for updates ([captured update sequence][update-sequence]). This catalog records device-reported HIDs and separately labels identifiable firmware filenames from Gree's update service or public firmware archives, plus identifiers embedded in published firmware-string dumps. Researched 2026-10-14.

## String segments

For example, `362001066763+U-W06A(P3)V6.04.bin` is a reported Sinclair air-to-water HID. This repository's [Sinclair trait profile](../greeclimate/device_profile.py) requires MID `9300` and firmware code `362001066763`, without constraining module or version, to enable cooling mode `5`. [Family selection](../greeclimate/device_factory.py) requires only MID `9300` and happens before HID is received.

| Segment | Interpretation | Limits |
| --- | --- | --- |
| `362001066763` | Firmware code, used as `firmwareCode` in Gree's update API. | Treat the complete digit string as an opaque identifier. Its subfields have no verified decoding here, and code lengths vary. |
| `+` | Separator between the numeric code and firmware name. | Not part of the filename prefix. |
| `U-` | Literal prefix within the firmware name. | Its expansion is not verified; some firmware filenames have no such prefix. |
| `W06A` | Module/platform designation. | [INFERENCE] This role follows the naming pattern; individual characters are not decoded. `CS532AE(LT)` is independently documented as a Wi-Fi module name ([Gree certification][module-certification]). |
| `(P3)` | Qualifier attached to the designation. | [INFERENCE] A platform/firmware variant label; no verified expansion of `P3`. It does not establish protocol version 3. Qualifiers such as `LT`, `MTK`, and `MTK2` must not be assumed to have the same meaning. |
| `V6.04` | Firmware version, preserved as the string `6.04`. | Do not convert to a number or compare across firmware families. The communication protocol version is a separate update-API field, `commProtVer`. |
| `.bin` | Binary firmware-image filename extension. | Some download filenames use other naming schemes; not every downloadable image is a reported HID. |

The device's reported `version` extracts only the terminal `V<digits/dots>.bin` suffix ([implementation](../greeclimate/device.py)). The [trait matcher](../greeclimate/device_profile.py) separately parses the received HID into firmware code, module designation (excluding `U-` and any parenthesized qualifier), and literal version. Every specified profile criterion must match, including MID when present; the first matching profile wins without merging. ATW traits resolve from the latest received HID on the existing instance, without changing its class. MID is separate discovery metadata, not an HID segment; see [MIDS.md](MIDS.md). A firmware code can appear on multiple appliance models, so neither the code nor the module designation alone proves the appliance model, capabilities, or a safe firmware replacement.

## Catalog conventions

- **Reported** means a public device log, status response, or owner's explicit HID report. **Archive** means an identifiable firmware filename associated with a code in the firmware archive. **Gree** means an identifiable filename in the official service's `Content-Disposition` header. **Firmware** means a literal identifier in a published firmware-string dump, not a running-device observation. **Local** means this repository's explicit device profile, not an independently verified web report.
- `Unknown` means the checked sources do not establish the value. `None` means that the observed filename has no prefix or parenthesized qualifier, rather than missing evidence.
- Versions are literal HID/identifiable-filename/embedded-identifier suffixes, not arbitrary versions returned by the update API. Server-added numeric filename suffixes are excluded. Generic filenames such as `ota_sdkshell`, bare firmware-code lists, and synthetic test inputs do not establish additional HIDs.
- Multiple values use bullet lists within a cell. These are aggregated observations, **not a Cartesian product**: not every name, module, qualifier, or version combination is a confirmed HID. Follow the row's sources for exact strings and associations.
- Names and MIDs are included only where explicitly associated with the reported HID/code or the local profile. No MID is inferred from an appliance category. This is a sourced snapshot, not an exhaustive registry or a firmware-upgrade compatibility list.

## Evidence notes and exceptions

- Firmware codes are sorted numerically and preserved exactly, without padding. `36300000257` is an 11-digit archive code. Its `CS532RV41` filename is split literally as designation `CS532R` and version `41`; this is **not** a reported HID, and is not normalized to the separately recorded OTA API version `4.1`.
- For `362001065232`, `IC程序` is an extra filename label before `U-`. The table preserves the complete observed filename prefix `IC程序U-`; it does not assert that a device reports that prefix in its HID.
- For `362001065634`, the owner writes the HID as `[362001065634]+U-WB04BRT13V1.44.bin` ([report](https://github.com/home-assistant/core/issues/176486#issuecomment-5217448314)). The table groups the numeric code; the brackets are preserved here as written, and their presence in the device's raw HID is unverified. The report supplies neither an appliance model nor a MID.
- For `362001065279`, the Cooper & Hunter report is associated with received-packet HID `1.05` and MID `10001`, Bora A5 with reported `1.21`, Heiwa Essential ZEN+ with reported `1.23`, and Lomo Nordic with the contributor's archived `1.26` filename. These are not model assignments for every version in the row.
- For `362001068254`, Airy `GWH12AVCXD-K6DNA1A` is reported with `2.09` and MID `10001`; Airy `GWH09AVCXB-K6DNA1B/I` with `2.11`/`2.12`; and Clivia with `2.12`. The latter reports do not supply MIDs. For `362001067541`, the named indoor/outdoor models and code are in a later comment by the same owner who previously supplied the `2.10` HID.
- Issue #176486 also discusses OTA metadata versions `2.01` and `2.09` for `362001067541`, without reporting complete HIDs for those versions ([comment](https://github.com/home-assistant/core/issues/176486#issuecomment-6061164102)). They are not added as observed HID versions.
- For `362001066763`, the same owner reports `6.04` for both Sinclair models and supplies MID `9300` in the linked gree-remote issue. The local profile matches that MID and firmware code, irrespective of module or version. A separately checked official download header names `U-W06A(P3)V6.0-5121008307837131559.bin`; `6.0` is catalog-only and does not replace the reported `6.04`.
- The official service also named `U-BL3332_JDV18-14745487806682515130.bin` for `362001061383` when checked. This supplies the catalog-only `18`, separately from the reported `1`. Links labeled **Gree** point to the metadata endpoint whose image URL supplied the checked filename header; those live responses may change.
- `362001065736` version `3.78` is explicitly **test firmware**. Its embedded identifier proves a firmware artifact exists, not that it was installed, generally released, or is safe to flash.
- Generic-only archive folders such as `36200100812` and `362001063066`, the archive's bare known-code list, and API metadata without an identifiable firmware name are excluded: they establish codes or update records, not decodable HIDs. A missing row is not evidence that a device is unsupported.
- Versati reports mentioning MID `9300` and software `V6.04` without a complete HID do not establish the Sinclair firmware-code association; no Versati HID was invented from those fields ([community report][versati-report]).
- For `362001061665`, issue #109230 names `GWH09AGA-K6DNA1A/I` and its linked log reports `2.06`; issue #124007's log supplies `1.21` and `2.01` without a retail model. All three variants have MID `10001` matched to the same device's discovery and status packets. The `362001063794` log supplies MID `10002` but no retail model; nearby U-Crown reports are from other owners and are not assigned to it.
- For `362001065280`, `1.09` is reported by the runtime log in issue #123755, without a same-device MID. Issue #109230 comment 2097199452 explicitly supplies `1.16` and `1.21` with MID `10001`; the row's MID must not be assumed for every version.
